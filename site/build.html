Build & extend

Both projects are plain Maven builds — one command produces the jar. Below: toolchain, artifacts, project layout and the usual extension points.

Building from source

Toolchain

bukkitJDK 8 or newer3.6+--release 8

Commands

defaultGoal is already set to clean package, so plain mvn is enough:

# Bukkit build
cd CreeperConfettiPro-bukkit
mvn clean package

# Folia build
cd CreeperConfettiPro-folia
mvn clean package

Artifacts land in each project's target/:

CreeperConfettiPro-4.1.0-bukkit.jar          # the plugin, ~850 KB
original-CreeperConfettiPro-4.1.0-bukkit.jar # pre-shade thin jar — do not use

The original- prefix marks the shade plugin's intermediate output. It has no bStats classes and fails on enable with NoClassDefFoundError.

  <pattern>org.bstats</pattern>

The build also writes dependency-reduced-pom.xml to the project root. That is normal shade behaviour; usually you ignore it in version control.

!

Both poms enable resource filtering (<filtering>true</filtering>), so ${...} inside src/main/resources is substituted by Maven. Escape it or avoid the pattern when writing language files.

Extension points

Adding a subcommand

  1. Extend BaseSubCommand in commands/sub/ and implement getName(), getPermission(), getDescriptionKey() and execute();
  2. call register(new YourCommand()) in the CreeperConfettiCommand constructor;
  3. add the permission node to plugin.yml and attach it to the creeperconfetti.command children;
  4. add help.sub.xxx plus your message keys to all 18 language files (missing keys fall back to English).

Keep the damage, drop the crater

The default cancels the whole explosion. If you want "damage and knockback, intact terrain", do not call setCancelled — clear the block list and spawn the firework instead:

@EventHandler
public void onCreeperExplode(EntityExplodeEvent event) {
    if (event.getEntity().getType() != EntityType.CREEPER) return;

    Creeper creeper = (Creeper) event.getEntity();
    Location location = creeper.getLocation().add(0, 1, 0);

    // only clear the affected blocks, keep damage and knockback
    event.blockList().clear();

    FireworkUtil.spawnAndDetonate(plugin, location,
            plugin.getFireworkStyleManager().getRandomEffects(), 0);
}
i

With this approach the creeper is not removed, so the firework appears alongside the explosion. To remove it as well, call creeper.remove() after the event — and on the Folia build wrap it in Schedulers.runOnEntity.

Restrict to specific worlds

The world name is right there in the event; one guard is enough (there is no built-in switch for this):

if (!creeper.getWorld().getName().equals("world")) return;

Supporting another colour format

Parsing lives in FireworkEffectParser.parseColor(), which dispatches by type: Color, Number, String, ConfigurationSection, Map. A new format is one extra branch; nothing else has to change.

v

If you change the config schema, increment ConfigMigrator.CURRENT_VERSION and add the conversion in migrate() — otherwise existing users end up missing fields after an update.

扩展点

新增一个子命令

  1. 在 commands/sub/ 下继承 BaseSubCommand，实现 getName()、getPermission()、getDescriptionKey()、execute()；
  2. 在 CreeperConfettiCommand 构造函数里 register(new YourCommand())；
  3. 在 plugin.yml 的 permissions 下加权限节点，并挂到 creeperconfetti.command 的 children；
  4. 在 18 个语言文件里补 help.sub.xxx 与提示文案（缺了会回退英文）。

保留伤害，只去掉方块破坏

默认实现是取消整个爆炸。如果你想要「有伤害、有击退，但地面完好」，不要 setCancelled，改为清空方块列表并额外生成烟花：

@EventHandler
public void onCreeperExplode(EntityExplodeEvent event) {
    if (event.getEntity().getType() != EntityType.CREEPER) return;

    Creeper creeper = (Creeper) event.getEntity();
    Location location = creeper.getLocation().add(0, 1, 0);

    // 只清空被破坏的方块，保留伤害与击退
    event.blockList().clear();

    FireworkUtil.spawnAndDetonate(plugin, location,
            plugin.getFireworkStyleManager().getRandomEffects(), 0);
}
i

这种方式下苦力怕不会被移除，烟花会和爆炸同时出现。想彻底不留苦力怕，仍然需要 creeper.remove()，但要放在事件处理之后——Folia 分支请用 Schedulers.runOnEntity 包一层。

只对指定世界生效

事件里能直接拿到世界名，加一行判断即可（当前版本没有内置这个开关）：

if (!creeper.getWorld().getName().equals("world")) return;

支持新的颜色写法

颜色解析集中在 FireworkEffectParser.parseColor()，它按类型分派：Color、Number、String、ConfigurationSection、Map。新增一种写法只需要在这个方法里加一个分支，其它代码不用动。

v

改完配置结构记得把 ConfigMigrator.CURRENT_VERSION 加 1，并在 migrate() 里补上转换逻辑，否则老用户升级后会缺字段。
